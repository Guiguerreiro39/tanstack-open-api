# Two-layer single-source Tailwind v4 token architecture, `[data-theme]` presets, and `DESIGN.md` contract

We centralize the entire visual system inside a single two-layer stylesheet (`src/styles/theme.css`, imported by `src/index.css`) paired with a domain-neutral `DESIGN.md` ("Warm Tactile Studio") and a reactive tri-state/preset theme controller (`src/shared/lib/theme.ts`). **Layer 1 (`:root`, `.dark`, and `[data-theme="<preset>"]`)** defines all runtime `Design Token`s: core `shadcn/ui` tokens (`--background`, `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`, `--chart-1..5`, `--sidebar-*`), extended Material-style surface hierarchy (`--surface`, `--surface-dim`, `--surface-bright`, `--surface-container-lowest|low|DEFAULT|high|highest`, `--on-surface`, `--on-surface-variant`, `--inverse-surface`, `--inverse-on-surface`, `--outline`, `--outline-variant`), extended accent containers (`--primary-container`/`--on-primary-container`, `--primary-fixed`/`--primary-fixed-dim`, `--secondary-container`/`--on-secondary-container`, `--tertiary`/`--tertiary-foreground`/`--tertiary-container`/`--on-tertiary-container`/`--tertiary-fixed`), semantic status pairs (`--destructive-container`/`--on-destructive-container`, `--success*`, `--warning*`, `--info*`), font family variables (`--font-sans-family`, `--font-display-family`, `--font-mono-family`), the base radius seed (`--radius`), and switchable elevation/tactile interaction variables (`--shadow-color`, `--shadow-2xs..lg`, `--inset-shadow-input`, `--shadow-tactile`, `--shadow-tactile-hover`, `--shadow-tactile-active`, `--tactile-hover-translate-x/y`, `--tactile-active-translate-x/y`). **Layer 2 (`@theme inline` and `@utility`)** binds those variables into Tailwind v4 compiler tokens (`--color-*`, `--font-*`, `--text-display-lg` through `--text-label-sm`, `--radius-xs..4xl`, `--shadow-*`) and registers `@utility shadow-tactile` and `@utility interactive-tactile` (`&:hover:not(:disabled)` / `&:active:not(:disabled)`). We ship three built-in `Theme Preset`s (`warm-tactile` default, `editorial-slate` minimal SaaS with diffuse shadows, and `neo-brutalist` high-contrast studio), align native browser UI via `<meta name="color-scheme" content="light dark">` + `:root`/`.dark` `color-scheme` and an inline SSR FOUC-prevention script in `src/routes/__root.tsx`, standardize on `lucide-react` icons, and enforce zero hardcoded component styles via a Vitest theme-hygiene test (`src/shared/ui/__tests__/theme-hygiene.test.ts`).

## Considered Options

- **Keeping `forklore-fe`'s split `DESIGN.md`, `src/index.css`, and inline component hex classes (`bg-[#fff8f3]`, `text-[#9f3c16]`, `.chunky-shadow`)**: Rejected because omitting `--surface-*`, `--on-surface-*`, `--primary-container`, `--tertiary*`, and `--destructive-foreground` from `@theme inline` forced 110+ hardcoded hex utility occurrences across 9 files and caused 3-way drift between `DESIGN.md` (`#fef8f4`, `#a93201`, `Quicksand`), `src/index.css` (`#fff8f3`, `#9f3c16`, `Inter Variable`), and `src/routes/__root.tsx` (`Newsreader`, `Plus Jakarta Sans`, `Quicksand`).
- **Declaring literal color values directly inside `@theme { --color-primary: ... }` instead of `@theme inline { --color-primary: var(--primary); }`**: Rejected because `@theme inline` compiles utility classes directly to `var(--<token>)` and opacity modifiers (such as `border-outline-variant/40`) to runtime `color-mix(in oklab, var(--outline-variant) 40%, transparent)`, allowing `.dark` and `[data-theme="<preset>"]` overrides in Layer 1 to use either `oklch(...)` or `#hex` without duplicating Tailwind's `--color-*` namespace.
- **Loading both `Material Symbols Outlined` Google Fonts and `lucide-react`**: Rejected because `shadcn/ui`'s 62 registry components natively depend on `lucide-react`, and dropping the extra Google Fonts icon stylesheet eliminates render-blocking font weight downloads and inconsistent `<span className="material-symbols-outlined">` markup.
- **Relying solely on client-side React effects (`useEffect`) or `.dark` classes without `<meta name="color-scheme">` and `:root` `color-scheme`**: Rejected because SSR pages flash un-themed canvas backgrounds before hydration and leave root scrollbars and native form controls stuck in light mode unless `<meta name="color-scheme" content="light dark">`, `:root` `color-scheme`, and a synchronous inline `<head>` script coordinate before first paint.

## Consequences

- Restyling the entire application requires editing only Layer 1 of `src/styles/theme.css` (and its human/agent contract in `DESIGN.md`), or toggling `data-theme="warm-tactile" | "editorial-slate" | "neo-brutalist"` and `.dark` at runtime via `useTheme()` (`src/shared/lib/theme.ts`).
- All 62 `shadcn/ui` primitives in `src/shared/ui/` inherit the semantic and tactile tokens out of the box (`Button` uses `interactive-tactile` and `rounded-xl`; `Card` uses `rounded-2xl border-outline-variant/40 bg-card shadow-tactile`; `Input`/`Textarea`/`Select` use `rounded-xl bg-surface-container-lowest shadow-(--inset-shadow-input)`).
- `src/routes/__root.tsx` loads `Quicksand`, `Plus Jakarta Sans`, and `JetBrains Mono`, injects `<meta name="color-scheme" content="light dark" />` plus the synchronous `try/catch`-guarded FOUC-prevention `<script>`, and renders `<body className="bg-background text-foreground font-sans antialiased min-h-screen">` with zero hardcoded hex classes.
- `src/shared/ui/__tests__/theme-hygiene.test.ts` runs in `pnpm test` and fails CI if any `.ts` or `.tsx` file under `src/` introduces arbitrary hex/rgb/hsl/oklch Tailwind utilities, inline color/shadow style literals, or legacy `.chunky-shadow` classes.
