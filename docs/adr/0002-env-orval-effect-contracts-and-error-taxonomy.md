# Split client/SSR Effect environment config, dual-target Orval v8 codegen, and typed HTTP error taxonomy

We validate environment variables in `src/shared/config/env.ts` using split Effect `Schema` definitions (`ClientEnvSchema` for `VITE_*` variables and `ServerEnvSchema` guarded by `typeof window === "undefined"` for SSR-only variables like `API_INTERNAL_URL`, `NODE_ENV`, `PORT`, and `HOST`), exposing `parseEnv` and `resolveApiUrl` while banning direct `process.env` / `import.meta.env` reads across `src/**` via Biome `style/noProcessEnv`. We configure `orval.config.ts` with two targets against the committed `./openapi.json` spec (`client: "react-query"` with `override.fetch.includeHttpResponseReturnType: false` and `useInfiniteQueryParam: "cursor"`, plus `client: "effect"` with `override.effect.generateEachHttpStatus: true` and `useDates: false`), and pair them via `defineContract` (`src/shared/api/contracts.ts`) to infer `OperationErrorStatuses<Op>` directly from the generated `@orval/effect` schemas without hand-written DTO structs. `customFetch` (`src/shared/api/client.ts`) normalizes `hono-open-api`'s `{ error: { code, message, requestId, details? } }` error envelope and `X-Request-Id` header into `FetchError`, which `decodeApiError` maps into 11 status-specific `Data.TaggedError` classes (`BadRequestError` `400` through `ServiceUnavailableError` `503`), `UnknownError`, and `SchemaDecodeError`.

## Considered Options

- **Single-target Orval (`client: "react-query"`) + manual `src/shared/api/dto/*.dto.ts` Effect schemas**: Rejected because duplicating every OpenAPI schema by hand in `dto/*.dto.ts` creates maintenance toil and silent contract drift, whereas `@orval/effect` with `generateEachHttpStatus: true` emits Effect `Schema` validators for all `200`/`201` responses, request bodies, query params, and error statuses automatically.
- **Orval v8 default `includeHttpResponseReturnType: true` and `override.useDates: true`**: Rejected because `customFetch` returns unwrapped `response.json()` payloads and TanStack Query SSR dehydration serializes timestamps as ISO strings; leaving `includeHttpResponseReturnType: true` or `useDates: true` causes Orval's TypeScript return types to diverge from runtime JSON data and breaks `TQueryFnData extends I` compile-time checks in `useEffectQuery` and `useEffectMutation`.
- **Single flat `VITE_*` env schema or `@t3-oss/env-core`**: Rejected because SSR requests inside Docker containers need `API_INTERNAL_URL` (e.g., `http://api:9999`) while browser requests use `VITE_API_URL` (same-origin `""` or host URL), and Effect `Schema` already provides standard validation without an external env library.
- **Single generic `HttpError` class instead of status-tagged `Data.TaggedError` classes**: Rejected because per-status `Data.TaggedError` classes (`BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`, `RequestTimeoutError`, `ConflictError`, `PayloadTooLargeError`, `ValidationError`, `RateLimitError`, `InternalServerError`, `ServiceUnavailableError`) enable exhaustive `Effect.catchTag` handling in UI components and form submission flows.

## Consequences

- `orval.config.ts` emits `src/shared/api/generated/endpoints.ts`, `src/shared/api/generated/models/`, and `src/shared/api/generated/schemas.ts`; both `./openapi.json` and `src/shared/api/generated/**` are committed to git, ignored by Biome via `!!src/shared/api/generated`, and checked for drift in CI via `pnpm generate:api && git diff --exit-code`.
- `customFetch` attaches `credentials: "include"`, `X-Request-Id`, and fallback W3C `traceparent` headers, omits default `"Content-Type": "application/json"` when `body instanceof FormData` (`POST /api/v1/files`), and returns `response.blob()` for binary downloads (`GET /api/v1/files/{id}/download`).
- `useEffectQuery` and `useEffectMutation` enforce `TQueryFnData extends I` and `TData extends I` at compile time, while `matchEffect` only renders `onPending()` when `isPending` is true (ignoring background `isRefetching` unless `showPendingOnRefetch: true`) and reports `SchemaDecodeError`, `InternalServerError`, and `UnknownError` defects to `ObservabilityPort`.
- Shared pagination helpers (`getNextCursorParam` and `isInvalidCursorError` matching `BadRequestError` with `code: "INVALID_CURSOR"`) standardize cursor pagination across `tasks` and `files`.
