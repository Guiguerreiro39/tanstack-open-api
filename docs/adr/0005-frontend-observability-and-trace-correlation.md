# Frontend `ObservabilityPort` seam, Sentry & Datadog browser adapters, and W3C `traceparent` correlation

We abstract all frontend telemetry behind `ObservabilityPort` (`Context.Tag("ObservabilityPort")<ObservabilityPort, ObservabilityService>()`) in `src/shared/observability/port.ts` with five methods (`initRouter`, `setUser`, `captureDefect`, `recordBreadcrumb`, `captureReactError`) and wire its active `Adapter` into `createAppRuntime` (`src/app/runtime.ts`) from validated `ClientEnvSchema` keys (`src/shared/config/env.ts`): `NoopObservabilityAdapter` in `test` mode (or unconfigured production builds), `ConsoleObservabilityAdapter` in unconfigured `DEV` mode, `SentryObservabilityAdapter` (`@sentry/tanstackstart-react` with `tanstackRouterBrowserTracingIntegration`, masked `replayIntegration`, and `reactErrorHandler`) when `VITE_SENTRY_DSN` is set, `DatadogObservabilityAdapter` (`@datadog/browser-rum`, `instrumentTanstackRouter` from `@datadog/browser-rum-react/tanstack-router`, `addReactError` from `@datadog/browser-rum-react`, and `@datadog/browser-logs` with shared `{ clientToken, site, service, env, version }` and `defaultPrivacyLevel: "mask-user-input"`) when `VITE_DD_APPLICATION_ID` and `VITE_DD_CLIENT_TOKEN` are set, and `CompositeObservabilityAdapter` when both providers are enabled. We correlate every HTTP and SSE request with `hono-open-api` by guaranteeing outbound `X-Request-Id` and W3C `traceparent` (`00-<traceId>-<spanId>-01`) headers in `customFetch` and `useLiveQuery` (setting Sentry `propagateTraceparent: !isDatadogRumActive` to prevent dual-SDK header overwrites), attaching `{ requestId, traceId }` to `FetchError` and all `ADR-0002` `Data.TaggedError` classes, and alerting only on unexpected `Defect`s (`SchemaDecodeError`, `500`/`503`/`UnknownError`, and React 19 root/boundary errors) while recording expected `4xx` domain errors as PII-safe breadcrumbs.

## Considered Options

- **Calling `Sentry.*` and `datadogRum.*` directly across `client.ts`, `router.tsx`, and query hooks**: Rejected because scattering vendor SDK calls across feature slices and transport hooks couples callers to two distinct third-party APIs, requires external accounts or global mocks in Vitest, and makes dual-provider fan-out (`CompositeObservabilityAdapter`) error-prone.
- **Wrapping `createTanStackRouter` with Datadog's custom `createRouter` wrapper**: Rejected because replacing `@tanstack/react-router`'s router factory prevents cleanly composing Sentry's `tanstackRouterBrowserTracingIntegration(router)` on the same instance, whereas `instrumentTanstackRouter(router)` subscribes to `router.subscribe("onResolved", ...)` without altering router construction.
- **Relying solely on Sentry/Datadog browser SDKs to inject `traceparent` and omitting `X-Request-Id` / fallback `traceparent` in `customFetch`**: Rejected because local development, SSR requests, and Vitest runs often execute without Sentry or Datadog configured, and enabling both SDKs simultaneously with `traceparent` injection causes header collisions; coordinating `propagateTraceparent: !isDatadogRumActive` with a deterministic `createW3CTraceparent()` fallback in `customFetch` guarantees `hono-open-api`'s `requestId()` and `traceContext()` middleware always log correlated `requestId` and `trace_id` values.
- **Reporting all failed queries and mutations (`4xx` and `5xx`) in `QueryCache.onError` / `MutationCache.onError`**: Rejected because expected `4xx` domain errors (`401`, `403`, `404`, `409`, `422`) represent normal control flow and form validation that would flood Sentry Issues and Datadog Error Tracking with false-positive alerts, and reporting in both `useEffectQuery` and `QueryCache.onError` would duplicate every defect report.

## Consequences

- `ClientEnvSchema` (`src/shared/config/env.ts`) validates optional telemetry configuration with safe defaults (`VITE_APP_VERSION` `"0.0.0"`, `VITE_SENTRY_DSN`, `VITE_SENTRY_TRACES_SAMPLE_RATE` `0.2`, `VITE_SENTRY_REPLAY_SAMPLE_RATE` `0.1`, `VITE_DD_APPLICATION_ID`, `VITE_DD_CLIENT_TOKEN`, `VITE_DD_SITE` `"datadoghq.com"`, `VITE_DD_SERVICE` `"tanstack-open-api-web"`, `VITE_DD_SESSION_SAMPLE_RATE` `100`, `VITE_DD_REPLAY_SAMPLE_RATE` `20`, `VITE_DD_TRACE_SAMPLE_RATE` `100`), and all browser SDK `init` calls are guarded by `typeof window !== "undefined"`.
- `FetchError` and all 11 status-specific `Data.TaggedError` classes (`BadRequestError` through `ServiceUnavailableError`), `UnknownError`, and `SchemaDecodeError` carry optional `readonly requestId?: string` and `readonly traceId?: string` properties populated from `errorData?.error?.requestId ?? response.headers.get("X-Request-Id") ?? outboundRequestId` and the outbound `traceparent`.
- `useEffectQuery`, `useEffectMutation`, `useLiveQuery`, and `authSessionQueryOptions` invoke `observability.captureDefect` once at the contract decode seam for `SchemaDecodeError`, `InternalServerError` (`500`), `ServiceUnavailableError` (`503`), and `UnknownError`, and call `observability.recordBreadcrumb` (redacting raw form input values on `422 ValidationError`) for expected `4xx` domain errors.
- `getRouter` calls `observability.initRouter(router)`, `src/client.tsx` wires React 19's `onUncaughtError`, `onCaughtError`, and `onRecoverableError` root hooks to `observability.captureReactError`, and the `ADR-0003` auth session lifecycle calls `observability.setUser(user)` on login/hydration and `observability.setUser(null)` on sign-out or `401` session reset.
