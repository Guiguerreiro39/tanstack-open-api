# Dual-transport SSE `useLiveQuery` hook, Effect-validated snapshots, and optimistic `tasks` mutations

We redesign `useLiveQuery` in `src/shared/lib/hooks/use-live-query.ts` to pair with `hono-open-api`'s SSE protocol (`GET /api/v1/tasks/live`) without `?token=` query-string authentication: by default it opens a browser `EventSource(resolveApiUrl(liveUrl), { withCredentials: true })` (guarded by `typeof window !== "undefined"` for SSR), and when a `bearerToken` string or getter is provided it switches to `fetch()` + `eventsource-parser` (`createParser`) with `Authorization: Bearer`, `Accept: "text/event-stream"`, `X-Request-Id`, and `traceparent` headers, honoring `retry: 3000` with exponential backoff (`baseDelayMs = 1_000`, `maxDelayMs = 30_000`) on transient failures (`429`, `502`, `503`, `504`, network drops) and halting retries on non-retryable `4xx` responses (`400`, `401`, `403`, `404`, `422`). Both `init` and `update` SSE frames are validated through `Schema.decodeUnknownEither(descriptor.dataSchema)` before calling `queryClient.setQueryData`, `error` frames are decoded via `decodeApiError` into `ADR-0002` `AnyApiError` classes, `ping` frames update `lastPingAt`, `staleTime` is set to `Number.POSITIVE_INFINITY` while `liveStatus === "connected"`, incoming SSE snapshots are buffered in a ref while `queryClient.isMutating({ mutationKey }) > 0` so concurrent optimistic `tasks` mutations (`create`, `patch`, `delete`) are never clobbered mid-flight, and `.toEffect()` enforces non-blocking stream degradation against its typed contract error channel.

## Considered Options

- **Appending `?token=<jwt>` to `new EventSource(url)` or adding a stateful SSE ticket endpoint**: Rejected because `hono-open-api` (`ADR-0008`) rejects query-string tokens with `401 UNAUTHORIZED` per RFC 6750 §2.3, whereas `EventSource(..., { withCredentials: true })` handles `HttpOnly` session cookies natively and `fetch()` + `eventsource-parser` supports explicit Bearer tokens without extra backend state.
- **Failing `.toEffect()` immediately on SSE stream errors when cached query data exists**: Rejected because transient SSE reconnects, network drops, or backend restarts would tear down or flicker active UI components (replacing working views with error alerts); non-blocking stream degradation ensures `.toEffect()` succeeds with cached data while the stream reconnects in the background, only failing with `streamError` when no cached data exists.
- **Listening only to `event: update` and writing raw `JSON.parse(event.data)` to `queryClient.setQueryData`**: Rejected because `hono-open-api` sends `event: init` both on initial stream open and on every reconnect (`retry: 3000`, without `Last-Event-ID` ring buffers), so ignoring `init` drops reconnect resynchronization, and writing unvalidated JSON bypasses the Effect `Contract` boundary and risks cache corruption.
- **Unconditionally calling `queryClient.invalidateQueries` in `onSettled` and applying SSE `update` frames while mutations are in flight**: Rejected because `hono-open-api` publishes `tasks:<userId>` and `tasks:all` events prior to returning `201`/`200`/`204` mutation responses; unconditional `invalidateQueries` triggers redundant `GET /api/v1/tasks` refetches when SSE is already pushing the authoritative snapshot, and unbuffered SSE `update` frames arriving during rapid sequential mutations clobber the second mutation's optimistic state.

## Consequences

- `useLiveQuery` exposes a typed error channel inferred from the contract descriptor (`OperationErrorStatuses<Op>`). Its `.toEffect()` implementation enforces non-blocking stream degradation: when cached data exists (`queryResult.data !== undefined`), `.toEffect()` succeeds with cached data (`Effect.succeed(queryResult.data)`) so transient SSE reconnects do not tear down the UI; it fails with `streamError` (`Effect.fail(streamError)`) only when no data is cached.
- `useLiveQuery` returns `{ ...queryResult, liveStatus: "idle" | "connecting" | "connected" | "reconnecting" | "error", streamError, lastPingAt }`, reports `SchemaDecodeError` defects on malformed `init`/`update` payloads to `ObservabilityPort` without mutating the Query cache, and triggers the `ADR-0003` session reset (`authSessionQueryOptions` -> `null` + `router.invalidate()`) if an SSE `error` frame or Bearer handshake returns `UnauthorizedError` (`401`).
- `useLiveTasks(params)` in `src/features/tasks/api/use-live-tasks.ts` passes URL-validated search params (`cursor`, `limit`, `scope: "own" | "all"`, `userId`) to both `getGetApiV1TasksQueryOptions(params)` and `getGetApiV1TasksLiveUrl(params)`, and automatically recovers from `isInvalidCursorError` (`400 INVALID_CURSOR`) by clearing `cursor` in route search params (`replace: true`).
- Task mutation hooks (`useCreateTask`, `useUpdateTask`, `useDeleteTask`) share the `["tasks", "mutation"]` key prefix, cancel outgoing task queries and apply optimistic cache updates in `onMutate`, merge authoritative `TaskDto` payloads in `onSuccess`, roll back from `context.previousQueries` in `onError`, flush any buffered SSE snapshot once `queryClient.isMutating({ mutationKey: ["tasks", "mutation"] })` drops to `0`, and only fall back to `queryClient.invalidateQueries` in `onSettled` when `liveStatus !== "connected"`.
