# Behavioral Vitest 4 strategy, outer-boundary `Test Harness`, and runtime verification skill

We configure Vitest 4 (`vitest.config.ts`) as a fast parallel `unit` project (`environment: "happy-dom"`, `fileParallelism: true`, `include: ["src/**/*.test.{ts,tsx}"]`, `setupFiles: ["./src/test/setup.ts"]`, `@vitest/coverage-v8` without percentage gates) combining `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom/vitest`, and `@effect/vitest`. We ban internal `vi.mock()` patching of application modules, `@/shared/lib/auth-client`, `@tanstack/react-query`, and `@tanstack/react-router`, and instead provide a unified `Test Harness` in `src/test/` that mounts the real `getRouter` and `createAppRuntime` `Composition Root` (`renderAppRoutes` and `renderWithProviders`) while intercepting strictly at the four outer I/O boundaries: HTTP `fetch` via MSW v2 (`msw/node` `setupServer` with `onUnhandledRequest: "error"`, `mockAuthSession`, and `honoErrorResponse`), SSE `EventSource` via `MockEventSource`, presigned upload `XMLHttpRequest` via `MockXMLHttpRequest`, and `ObservabilityPort` via `createSpyObservability()`. We complement Node-based unit/contract/component suites with a project-local runtime verification skill (`.agents/skills/verify-tanstack-open-api/SKILL.md` and a 5-feature map in `.agents/skills/verify-tanstack-open-api/features/`) that launches an isolated `tanstack-open-api` + `hono-open-api` instance, runs a read-only `doctor` check, drives user journeys through ARIA roles/labels, and records persistent proof artifacts.

## Considered Options

- **Mocking `@/shared/lib/auth-client`, `@tanstack/react-query`, `@tanstack/react-router`, and child UI components with `vi.mock()` (as in `forklore-fe`)**: Rejected because invoking `Route.options.beforeLoad` as a detached function or replacing `useQuery`/`<Link>` with stubbed return values bypasses TanStack Router's parent-to-child `/_app.tsx` guard inheritance, `validateSearch`, TanStack Query's cache state machine, `customFetch` error decoding, and Radix UI keyboard/pointer accessibility.
- **Overwriting `globalThis.fetch = vi.fn()` ad hoc per test file and using `fireEvent`**: Rejected because uncleaned `globalThis.fetch` mutations leak across tests, fail to intercept Better Auth (`authClient`) and Orval hooks uniformly, allow unhandled network calls to pass silently, and `fireEvent` misses realistic Radix UI / `shadcn/ui` pointer-capture and focus sequences that `@testing-library/user-event` exercises.
- **Running `@vitest/browser` (Playwright) inside every `pnpm test` run or keeping `jsdom` alongside `happy-dom`**: Rejected because `happy-dom` (`^20.x`) executes the Node-based contract, hook, form, and route suites 2–4x faster than `jsdom` without requiring Playwright browser binaries during inner-loop TDD, while full-stack real-browser CSS/SSR/SSE verification is handled end-to-end by `.agents/skills/verify-tanstack-open-api/`.
- **Enforcing hard coverage percentage thresholds in `vitest.config.ts`**: Rejected (matching `hono-open-api` `ADR-0011`) because percentage gates incentivize shallow assertions over thin glue rather than behavioral coverage of contracts, error taxonomies, and user flows.

## Consequences

- `src/test/` provides `msw-server.ts` (`server`, `mockAuthSession`, `honoErrorResponse`), `mock-event-source.ts` (`MockEventSource` for `withCredentials: true` SSE), `mock-xhr.ts` (`MockXMLHttpRequest` for presigned `PUT` byte-progress, abort, and `409` retries), `spy-observability.ts` (`createSpyObservability` implementing `ObservabilityPort`), `setup.ts` (`onUnhandledRequest: "error"`, `cleanup()`, `resetHandlers()`, and `happy-dom` pointer-capture/`ResizeObserver`/`scrollIntoView` shims), and `render-with-app.tsx` (`createTestQueryClient`, `renderAppRoutes`, `renderWithProviders`).
- Co-located `src/**/*.test.{ts,tsx}` suites are organized into three behavioral tiers: (1) contract, env, RBAC, and `ObservabilityPort` suites (`@effect/vitest` + MSW); (2) design-system and form primitive suites (`theme-hygiene.test.ts`, `theme.test.ts`, `form.test.tsx`); and (3) feature slice and route guard suites (`route-guards.test.tsx`, `auth`, `tasks`, `files`, `showcase`).
- `.agents/skills/verify-tanstack-open-api/SKILL.md` and `.agents/skills/verify-tanstack-open-api/features/` (`README.md`, `showcase-and-theming.md`, `auth-and-rbac.md`, `live-tasks.md`, `files-upload-and-download.md`, `observability-and-headers.md`) define the canonical runtime verification loop (`Launch`, `Doctor`, `Drive`, `Evidence`, `Cleanup`) against a live isolated `tanstack-open-api` + `hono-open-api` stack.
