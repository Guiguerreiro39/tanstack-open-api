# Release-Please automation, Conventional Commits governance, and GitHub Ruleset branch protection

We standardize the application template's release lifecycle on Google Release-Please (`googleapis/release-please-action@v4` with `release-type: node` over `"private": true` in `package.json`), maintaining a self-updating Release PR (`chore(main): release X.Y.Z`) that synchronizes `package.json#version`, `CHANGELOG.md`, git tags (`vX.Y.Z`), and GitHub Releases using only the built-in `GITHUB_TOKEN`. When a Release PR merges (`release_created == 'true'`), `.github/workflows/release.yml` builds and publishes multi-architecture OCI container images (`linux/amd64`, `linux/arm64`) to GitHub Container Registry (`ghcr.io`) via Docker Buildx and attaches Sigstore OIDC SLSA build provenance attestations (`actions/attest-build-provenance@v2`). We enforce Conventional Commits 1.0.0 across two tiers—remotely on Pull Request titles via `amannn/action-semantic-pull-request@v6` (`.github/workflows/pr-title.yml`) paired with Squash-and-Merge, and locally via Lefthook (`lefthook.yml`) running `@commitlint/cli` on `commit-msg` and staged Biome checks on `pre-commit`—while blocking direct pushes to `main` for non-authors via a local Lefthook `pre-push` guard (`ALLOW_DIRECT_MAIN_PUSH=1` override) and a declarative GitHub Repository Ruleset (`docs/github-ruleset.json` + `scripts/setup-github-rulesets.sh`) with Repository Admin (`actor_id: 5`) bypass, complemented by grouped Renovate dependency updates (`renovate.json5`).

## Considered Options

- **Changesets (`@changesets/cli` + `changesets/action`)**: Rejected because Changesets is designed for multi-package npm library monorepos and forces every PR author to run `pnpm changeset` locally and commit `.changeset/*.md` fragment files, creating unnecessary friction for an application template that does not publish packages to the npm registry.
- **Semantic-Release (`semantic-release`)**: Rejected because its push-driven model cuts tags and triggers production releases immediately on every push to `main` without a human review gate or previewable changelog PR, and requires orchestrating 5–8 plugins to support `"private": true` applications.
- **GitHub Native Automated Release Notes (`.github/release.yml`)**: Rejected because it only formats release notes in the GitHub UI upon manual tag creation and does not calculate semantic version bumps, update `package.json#version`, or maintain an in-repo `CHANGELOG.md`.
- **Husky (`v9`) + `lint-staged` (`v15`)**: Rejected because Husky + `lint-staged` adds 500–800ms of Node.js startup and glob-matching overhead on every commit, whereas Lefthook is a single compiled Go binary that executes staged Biome checks and Commitlint in parallel in under 35ms with native `stage_fixed: true` support.
- **Classic GitHub Branch Protection Rules**: Rejected because classic branch protection lacks layered rules, declarative JSON export/import ergonomics, evaluation mode, and granular `bypass_actors` configuration (such as separating Repository Admin role bypass from standard developer write access).
- **GitHub Dependabot (`.github/dependabot.yml`)**: Rejected because Dependabot opens noisy per-package PRs and lacks Renovate's ecosystem grouping (TanStack, React 19, Effect, Radix UI, Biome), native `chore(deps)` Conventional Commit formatting for Release-Please compatibility, and built-in devDependency automerge controls.

## Consequences

- `release-please-config.json` and `.release-please-manifest.json` configure Release-Please at the repository root (`.`) with `bump-minor-pre-major: true`, `bump-patch-for-minor-pre-major: true`, and structured `CHANGELOG.md` sections (`Features`, `Bug Fixes`, `Performance Improvements`, `Refactoring & Architecture`, `Documentation`, `Build System & Packaging`, `CI/CD & Governance`).
- `.github/workflows/release.yml` runs on pushes to `main`/`master` with `contents: write`, `pull-requests: write`, `packages: write`, `id-token: write`, and `attestations: write` permissions, gating multi-arch GHCR builds (`:X.Y.Z`, `:X.Y`, `:latest`, `:sha-<short>`) and SLSA provenance attestations strictly on `needs.release.outputs.release_created == 'true'`.
- `.github/workflows/pr-title.yml` validates all Pull Request titles against Conventional Commits types (`feat`, `fix`, `perf`, `refactor`, `docs`, `style`, `test`, `build`, `ci`, `chore`, `revert`) and lowercase subject rules using only `GITHUB_TOKEN`, ensuring Squash-and-Merge commits on `main` always feed clean metadata to Release-Please.
- `package.json` adds `lefthook`, `@commitlint/cli`, and `@commitlint/config-conventional` to `devDependencies` and updates `"prepare"` to `"effect-language-service patch && lefthook install"`, wiring `lefthook.yml` (`pre-commit` Biome staged autofix, `commit-msg` Commitlint validation, and `pre-push` direct-`main`-push prevention) and `commitlint.config.mjs`.
- `docs/github-ruleset.json` and `scripts/setup-github-rulesets.sh` provide a one-command (`gh api --method POST /repos/:owner/:repo/rulesets --input docs/github-ruleset.json`) provisioning path for template clones, enforcing PR merges and `verify`, `docker`, and `Lint PR Title (Conventional Commits)` status checks while allowing the repository owner/admin (`RepositoryRole` ID `5`) to bypass restrictions when needed.
- `renovate.json5` groups ecosystem updates and formats dependency PRs as `chore(deps): ...` so automated maintenance never triggers unintended minor or major application releases.
